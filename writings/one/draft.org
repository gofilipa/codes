*** web scraping
**** what is web scraping?

***** from bytes to HTML 

Web scraping is the extraction of information from websites. It most
often involves (with some exceptions, explained below) working with
data in HTML format, with elements and attributes.

#+begin_src html
  <!DOCTYPE html>
  <html>
  <body>

  <h1 class="header">First level heading element</h1>

  <p>A paragraph element with a <a href="/">link</a> inside of it</p>

  </body>
  </html>
#+end_src

Websites are stored in web servers, accessed over a network. Web data
travels over the network in the form of bytes, the smallest digitally
addressable data unit. When the bytes reach the web browser, they are
re-encoded into HTML language, which is assembled into a web page
readable by human eyes.

***** HTTP

Web /scraping/ is possible by manipulating HTTP, or HyperText Transfer
Protocol, which is the language of the network. A web scraper uses
code to manipulate an HTTP request so that it receives the website
data in the form of code.

Web scraping is, at its core, about mimicking a typical browser
request. Using HTTP protocols, it makes a request to a web server much
like a user makes a request by typing in a URL into the browser. The
data it gets back from the HTTP request is also the same as the data
that comes to a browser after searching a URL---only the data is
intercepted before in the form of bytes, rather than assembled into a
web page visible through a browser.

#+begin_src python
  r = requests.get("https://www.nytimes.com/")
#+end_src

You can scrape a website with only five lines of code. Below is an
example that scraps the home page of /The New York Times/ website
using the ~bs4~ and ~requests~ libraries in python.

#+begin_src python
from bs4 import BeautifulSoup
import requests

r = requests.get("https://www.nytimes.com/")
source = r.content
soup = BeautifulSoup(source, 'html.parser')
#+end_src

The ~requests~ library is one of the most popular libraries in the
python programing language. Enabling programs to send and receive data
through HTTP networks (i.e., the internet), it is the bedrock for
virtually all web scraping and API tasks. The ~get()~ function from
~requests~ can access the /NYTimes/ homepage, which is saved in the
form of bytes via the ~content~ property. Then, using ~bs4~, a python
library for working with HTML data, the data is parsed into an object
called ~soup~ (following ~bs4~'s naming conventions), which is a
pythonic object of HTML data. 

The beauty of ~bs4~ is that it makes HTML---a notoriously fussy
language that is the reason why so many web frameworks exist in the
first place, attempting to abstract the user from working directly in
HTML---accessible through simple python syntax.

For example, the expression ~soup.title~ returns the following output: 

#+begin_src python
  >>> soup.title
  <title data-rh="true">The New York Times - Breaking News, US News, World News and Videos</title>
#+end_src

Similarly, other HTML elements can now be accessed using python
dot syntax.

#+begin_src python console
  >>> soup.p
  <p>Make sense of the day’s news and ideas.</p>

  >>> soup.a
  <a class="css-kgn7zc" href="#site-content">Skip to content</a>

  >>> soup.h1
  <h1 class="css-1dv1kvn">New York Times - Top Stories</h1>
#+end_src

Further properties like ~text~ (for just text) and functions like
~find()~ are also possible. Functions can be further specified when
combined with the ~class_~ parameter, to search the HTML with more
precision. Due to python syntax, they can also be chained together to
create complex expressions. These building blocks enable programmers
to navifate the HTML tree with granularity.

#+begin_src python console
  >>> soup.h1.text
  'New York Times - Top Stories'
  
  >>> soup.find('div', class_ = 'css-cfnhvx')
  <div class="css-cfnhvx" data-tpl="h"><a class="tpl-lbl css-5mgoji" data-tpl="l" href="https://www.nytimes.com/live/2026/07/09/world/iran-war-us-trump"><div class="css-xdandi" data-tpl="b"><p class="indicate-hover css-1ixq7yl">U.S. and Iran Sink Into Violent Cycle After Trading Strikes</p></div></a></div>

  >>> soup.find('div', class_ = 'css-cfnhvx').text
  'U.S. and Iran Sink Into Violent Cycle After Trading Strikes'
#+end_src

HTML classes for an element can be found by using built-in browser
tools like the web inspector. On the webpage, right click on the
relevant text and select ~inspect~ from the dropdown menu. The element
will be highlighted with information for the ~class~ attribute.[fn:2]

***** Blockers and the resistance

Web servers, unfortunately for the scraper, often block automated
requests to their data. They use various forms of "blockers" or
mechanisms that deny the HTTP request, sending back a code 403, or
"Forbidden" message.

Each year of the past few years, bot traffic has increased
exponentially, coming mostly from major tech and AI companies,
especially OpenAI, META, Google, and Anthropic. According to
Cloudflare, 2025 saw increases of 19% in bot traffic (See Fig #)
(Cloudflare, "From Googlebot to GPTBot: who’s crawling your site in
2025"). It is no surprise that traffic has increased mostly from these
companies, whose ML model training requires ever increasing amounts of
data.

[[./images/bot_rankings.png]]

As automated scrapers increase in frequency, so do the bot blockers.
Over the past two years, Cloudflare, which runs on 20% of total
internet pages and 50% of pages based in the US, has added increasing
bot detection like "Challenges" and "Turnstiles" to its web pages.
Some of these operate under the surface and virtually invisible to the
user, such as checking the HTTP request metadata like the
"User-Agent." By default, the User-Agent is set to the name of web
browser and operating system making the request. For example, my
Firefox browser running Mac OSX has the User-Agent ~Mozilla/5.0
(Macintosh; Intel Mac OS X 10.15; rv:152.0) Gecko/20100101
Firefox/152.0~. The python ~requests~ library, by contrast, sets the
User-Agent to ~python-requests/2.32.3~, making any HTTP request using
that library easy for blockers to detect.

Beyond examining HTTP request data, bot blockers will use JavaScript
code to check if the request is from a real web browser, rather than
from an automated program. JavaScript, which is a programming language
native to web browsers (and discussed in more detail in Chapter 4:
Text Display), can inject challenges for the browser to solve,
challenges which may or may not involve the user. All of these
challenges might require some processing from the browser, and
increasingly, they may require the user's interaction (to confirm that
the request comes from a real browser, not a bot). One popular
challenge is the "security verification" checkbox, which is
increasingly visible across the internet (See Fig #).

[[./images/verify.png]]

While these kinds of blockers are more advanced, there are ways of
overcoming them. One effective method involves using a virtual or
"ghost" browser through python libraries like ~selenium~. Instead of
sending an HTTP request via a python script, ~selenium~ routes the
request through an actual web browser---though one that is operated
remotely by the python script. When the program is running, a browser
window will open on its own, navigate to a web page, and click on
links, all without the input of the user. It looks like a "ghost" is
operating the computer. One major drawback to this method is that it
requires a virtual display, which many "headless" scraping servers do
not have, in order to access the data via the browser window. That
requirement, in addition to the increase in necessary processing
power, detracts large-scale web crawling.

At the same time, internet security companies like Cloudflare have
also moved to what they call a "permission-based model," where bots
must pay for seamless access to certain domains. A blog post frames
the new policy as the next logical step in the mass data extraction
environment.

#+begin_quote
For decades, the Internet has operated on a simple exchange: search
engines index content and direct users back to original websites,
generating traffic and ad revenue for websites of all sizes. This
cycle rewards creators that produce quality content with money and a
following, while helping users discover new and relevant information.
That model is now broken. AI crawlers collect content like text,
articles, and images to generate answers, without sending visitors to
the original source – depriving content creators of revenue, and the
satisfaction of knowing someone is viewing their content. (“Cloudflare
Just Changed How AI Crawlers Scrape the Internet-at-Large;
Permission-Based Approach Makes Way for A New Business Model”)
#+end_quote

The argument refers to the original purpose of large-scale web
crawling, which was to populate and otherwise assist search engines.
This activity of taking content in the form of search results was
legitimized in a famous copyright lawsuit against Google, /The Authors
Guild Inc., et al. v. Google, Inc./ (2015). In this case, the judge
ruled that search results, such as that from Google Books, were
considered "fair use" because they point users to the original source
without diminishing its value. As long as search engines direct
traffic to the original source, then there appears to be no
infringement. 
 
Cloudflare points out that today's scrapers and crawlers to do not
direct users back to the original source; rather, the AI training
process /severs/ the data completely from its context, including its
source.[fn:3] Web pages are taken from their context and compiled into
massive collections which are fed, bit by bit, into a machine learning
algorithm. The severed connection to the source cannot be monetized,
"depriving content creators of revenue... and satisfaction."

As a solution, Cloudflare is shifting their policy to protect media
outlets and publishers. They have begun to offer the "permission based
model," where companies must pay content creators for access to their
web data. If the scraper does not have explicit permission to retrieve
data, then they will be blocked. The announcement of Cloudflare's new
policy came with written endorsement from publishers and media
outlets. Roger Lynch, CEO of media conglomerate Condé Nast, which owns
/Vogue/, /The New Yorker/, /Architectural Digest/, /Vanity Fair/,
/Pitchfork/, /Wired/, /Bon Appétit/, /Ars Technica/, among others,
declares that, "Cloudflare’s innovative approach to block AI crawlers
... is a critical step toward creating a fair value exchange on the
Internet that protects creators, supports quality journalism and holds
AI companies accountable" (“Cloudflare Just Changed How AI Crawlers
Scrape the Internet-at-Large; Permission-Based Approach Makes Way for
A New Business Model”). Of course, there is no garuntee (or even
expectation) that such payments would reach the pockets of actual
content creators, authors, copywriters, artists, who are populating
these sites with their work. If the new policy rewards someone, its
not the original creator but the publisher who enters into agreements
with the tech companies. In that sense, the "fair value exchange"
cited by Lynch is in fact another way of further monetizing what is
already an extractive practice of capture.

*** the politcs of capture
**** the current data grab
We are in the midst of an intense acceleration of what Ulises A.
Meijas and Nick Couldry call a "data grab." The data grab is the heir
of colonialism's "land grab," the long process over several centuries
in which Europe, despite representing 8 percent of the world's
landmass, seized over 84 percent of its total territory (Mejias &
Couldry 5). According to Mejias and Couldry, this data grab took
traditional colonial processes of exploration, extraction, and
exploitation of resources and applied them to a new object, to data.
"[B]oth systems," they explain, "are founded on an appropriation of
the world’s resources, treating them as ‘just there’ for the taking.
Historically it was the territories... In the contemporary era, it is
human life, extracted in the form of data" (Mejias & Couldry 18).

The object, and particularly its digital nature, required new
strategies for capture that differ from those of land-based resources.
First, rather than partition zones of extraction in the form of land
territories, there has emerged the digital platform. The platform is a
digital space, which can range in scope from individual websites on
the internet to self-enclosed apps, which contains mechanisms that
gather up details of the user's identity and activity---not only that
which has been voluntarily given, but also that contained in hidden
codes and protocols that append all data traveling over the internet.
In more technical terms, the platform is a server location, from which
the user requests data (via the HTTP protocol), and in that request,
also sends some information to the server. Most recently, the best way
of tracking users is in the form of a "cookie," a bit of data which
the server assigns to the user and which can be used to track that
user's activity on that and other servers. (Although, cookies can also
be manipulated by users to simulate real web requests that can bypass
web blockers, as I demonstrate at the end of the chapter). 

If the first strategy takes advantage of technical protocols, the
second strategy takes advantage of legal ones. Besides new procedures
for capture, it is necessry also to create the proper pretense for it.
In traditional colonialism, Mejias and Couldry explain, this pretense
was explicitly coercive. They offer the example of the
/Requerimiento/, a document that the Spanish colonizers read to the
indigenous peoples of Americas as they entered their land and
villages. The document certified the Spanish authority, in the name of
the king and the church, to take the land, its resources and people,
under Spanish control. It declared all who heard it subject to the
crown, and any those who resisted to be violently subdued. Mejias and
Couldry compare this document to the "Terms of Service" agreement from
Google Chrome, which also makes claims upon the user, in particular on
the "Content" that a user inputs into the system. The 2007 version of
the TOS asserts that,
#+begin_quote
You give Google a perpetual, irrevocable, worldwide, royalty-free, and
non-exclusive license to reproduce, adapt, modify, translate, publish,
publicly perform, publicly display and distribute any Content which
you [the user] submit, post or display on or through, the Services.
(Rpt. in Mejias & Couldry 12).
#+end_quote
More recently, the wording of TOS has muted the explictness of this
language. Recent wordings of Google TOS, the authors point out, don't
need to be as assertive: "without most of us ever having read those
original terms and conditions.... the extraction of data is already
well underway" (Mejias & Couldry 12). The more recent strategy has
shifted from assertive to excessive and at times obscure language
(these TOS now occupy many pages). For example, the 2024 Google TOS,
which is now held on its own subdomain, https://policies.google.com,
phrases like "operating and improving the services" and "to customize
our services for you" offer the necessary cover for "using automated
systems and algorithms to analyze your content" ("License", "Google
Privacy and Terms"). Additionally, the TOS contains strange and
difficult to parse formulations, like "We need your permission if your
intellectual property rights restrict our use of your content. You
provide Google with that permission through this license" ("License",
"Google Privacy and Terms"). The meaning appears to be that Google
will need, yet already has obtained, permission from the user. But
what exactly is one giving permission for Google to do? The TOS does
not say. 

That is if one even bothers to read the terms of service. Whereas the
/Requerimiento/ relied on blunt language claiming an authority over
land and people, more recent TOS rely on the user not even checking
the terms. While these approaches, separated by centuries, differ
dramatically, they both rely on the user not knowing the extent of the
rights being taken from them. The /Requerimiento/, similar to
modern-day TOS, used a language that was obscure to its audience. As
Mejias and Couldry point out, "[the conquerors] read this document in
Spanish... to indigenous or First Nation peoples who did not speak
Spanish!" (13). The legal strategy, then, maintains this dependence on
a certain level of ignorance from the user.

Like land, the data of the world will be taken until it meets
sufficient resistance to stop it. Shoshana Zuboff, whose 2015 essay
""Big Other: Surveillance Capitalism and the Prospects of an
Information Civilization" (and followup 2018 book, /The Age of
Surveillance Capitalism: The Fight for a Human Future at the New
Frontier of Power/) helped to formalize the notion of capture by the
captial forces, what Zuboff calls the "logic of accumulation"
(78).[fn:4] Her essay analyzes papers written by Google’s Chief
Economist Hal Varian, where he discusses the potential of
"computer-mediated economic transactions" (Rpt. Zuboff 78). Varian
identifies four new kinds of business activities made possible by
computation, which are "data extraction and analysis," "new
contractual forms," "personalization and customization," and
"continuous experiments" (Zuboff 78). Most of these rely on the nearly
infinite streams of data that platforms can capture from users, and on
the fact that these streams are mostly hidden from view, thus creating
asymmetrical relationships between the consumer and the business,
which obviates the role of trust. As Zuboff explains, "New
possibilities of subjugation are produced as this innovative
institutional logic thrives on unexpected and illegible mechanisms of
extraction and control that exile persons from their own behavior"
(85).

"Surveillance" capitalism is not as new as Zuboff would have it. She
describes it alternately as "A new economic order," "A rogue mutation
of capitalism," " a new instrumentarian power" (from book, /The Age of
Surveillance Capitalism/). As critics like Simone Brown and Ruha
Benjamin point out, however, the surveillance logic has existed for
centuries. Indeed, slavery, as an economic order, could be described
in the same terms that Zuboff uses to describe surveillance
capitalism: "A parasitic economic logic in which the production of
goods and services is subordinated to a new global architecture of
behavioral modification" (from book, /The Age of Surveillance
Capitalism/). Brown's work surfaces the quantifying and policing
practices that Black people have endured since slave ships. More
recently, Benjamin shows how new technologies perpetuate older
patterns under the guise of technical values like "neutrality." While
"tech advances are sold as morally superior," as Benjamin points out,
"they could not exist without data produced through histories of
exclusion and discrimination" (5). Values such as "objectivity,
efficiency, profitability, and progress" work to effectively siphon
the creator from these legacies perpetuated in the product (Benjamin
7). She explains that "tech designers encode judgments into technical
systems but claim that the racist results of their designs are
entirely exterior to the encoding process" (Benjamin 11-12).

**** word meaning being co-opted: "freedom" to extract data
On January 23, the White House released an Executive Order meant to
clear the obstacles preventing technological "innovation" regarding AI
development. The goal of the order is "to sustain and enhance
America’s global AI dominance in order to promote human flourishing,
economic competitiveness, and national security," the order argues,
the United States "must develop AI systems that are free from
ideological bias or engineered social agendas" (The White House,
"Removing Barriers"). The Order called for an "Artificial Intelligence
Action Plan," and the White House Office of Science and Technology
Policy (OSTP) solicited recommendations from the public.

On March 13, 2025, OpenAI responded to the proposal to the OSTP,
offering a set of "recoommendations" for developing AI policy. All of
the points in the recommendations are framed via positioning against a
common enemy, the People's Republic of China (PRC). References to
"American-led AI" adopts language of American values like "freedom"
and "democracy," which are posed against PRC's "autocratic,
authoritarian AI." First, the recommendations assert a "freedom of
intelligence," defined as "the freedom to access and benefit from
AGI," presumably meaning consumer access to commercial products, like
ChatGPT (Lehane 2). Then, it claims the "freedom to innovate," whereby
American companies would be exempt from complying with "overly
burdensome state laws" around AI use, such as those requiring safety
and bias checks ("AI Laws and Regulation in the United States
(2026)"). Finally, there is a "freedom to learn," which is, rather
slyly, the freedom of machines (rather than human beings) to learn.
Here the proposal is referring to the protection of copyrighted
material, which hasn't been a practical issue for AI development
(companies like OpenAI are already indiscriminately scraping the web
to train their models), but is a legal issue currently being
arbitrated in courthouses across the US
(https://chatgptiseatingtheworld.com/aicopyrightcasetracker/). The
freedom to learn, as the proposal itself admits, is really the
"ability to learn from copyrighted material" without having to pay for
the content (Lehane 5). Like the freedom to innovate, this freedom
also derives its argumentative momentum from China's threatening
shadow.
#+begin_quote
The PRC is unlikely to respect the IP regimes of any of such nations
for the training of its AI systems, but already likely has access to
all the same data, putting American AI labs at a comparative
disadvantage while gaining little in the way of protections for the
original IP creators. (page 4)
#+end_quote
This framing is not quite faithful to the realities on the ground: the
US has, already, disregarded "IP regimes" to get access to "all the
same data." However, the remarkable hypocrasy around data theft comes
into the starkest illustration when discussing the "fair use"
exemption from copyright law.
#+begin_quote
The rapid advances seen with the PRC’s DeepSeek, among other recent
developments, show that America’s lead on frontier AI is far from
guaranteed. Given concerted state support for critical industries and
infrastructure projects, there’s little doubt that the PRC’s AI
developers will enjoy unfettered access to data—--including
copyrighted data—--that will improve their models. If the PRC’s
developers have unfettered access to data and American companies are
left without fair use access, the race for AI is effectively over.
America loses, as does the success of democratic AI. (9-10)
#+end_quote
While the US's access to the same data is "fair," China's access to
the same data is "unfettered"---despite there being no difference in
the datasets (something like the entire web) and the methods of web
scraping and web crawling, which are used to obtain them.

"Freedom" is strange in this context --- it's a US value, being
contrasted to China's "autocratic" values. Yet, freedom is deployed in
the service of making the US policy effectively more like that of
China's. The autocratic qualities of the PRC, which allows it to
develop its AI free of regulation and copyright considerations, is
